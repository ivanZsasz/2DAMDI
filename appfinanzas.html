Construyendo VELUT: Diario de Desarrollo de una Fintech PWA asistida por IA

La idea nació de una necesidad personal: quería una aplicación de finanzas que no solo fuera funcional, sino que se sintiera "premium", como las apps de banca privada, pero sin la complejidad de frameworks pesados como React o Angular. Decidí utilizar el IDE Antigravity y colaborar con un agente de IA para iterar rápido sobre la marcha.

El objetivo era ambicioso: crear una PWA (Progressive Web App) completa, alojada en Firebase, que pudiera instalarse como una app nativa en Android, usando puramente Vanilla JS para mantener el código limpio y ligero.

Fase 1: Del concepto básico al 'Glassmorphism'

Al principio, mi enfoque fue puramente funcional. Le pedí al agente una estructura básica: Login, Dashboard y una lista de gastos. Sin embargo, el primer obstáculo surgió de inmediato: el diseño era demasiado genérico y "plano". Parecía un prototipo de estudiante, no una app real.

🚧 Obstáculo La primera versión forzaba una vista de móvil en pantallas de escritorio, desperdiciando espacio y rompiendo la inmersión del usuario.
💡 Idea Decidí pivotar radicalmente el diseño. No quería solo "colores bonitos", quería Glassmorphism. Me inspiré en las tarjetas de crédito metálicas y en interfaces como las de Stripe o Revolut. Le pedí a la IA que reescribiera el CSS para usar transparencias, desenfoques (backdrop-filter) y una paleta oscura elegante ("Slate Dark Blue").

Fase 2: El reto de la UX móvil y los Modales

Con el diseño visual mejorado, me encontré con un problema de usabilidad grave al probar la app en mi teléfono.

🚧 Obstáculo Al intentar introducir un gasto, el teclado nativo del móvil salía y tapaba el campo de input. Además, tener el formulario siempre visible en el dashboard saturaba la vista.
💡 Solución e Idea Se me ocurrió que la mejor forma de manejar esto era imitar a las grandes apps financieras: usar Ventanas Modales (Bottom Sheets). Pero fui un paso más allá: en lugar de depender del teclado del móvil, diseñé un teclado numérico personalizado en HTML dentro del modal. Esto no solo solucionó el problema del espacio, sino que hizo que la experiencia de añadir gastos fuera mucho más rápida y táctil.

Fase 3: Integrando Inteligencia (OCR, Voz y APIs)

Una vez que la base operativa funcionaba ("Crear Gasto"), sentí que a la app le faltaba "magia". Quería reducir la fricción al máximo.

Aquí integré varias tecnologías que convirtieron la app en una herramienta mucho más potente:

  • Reconocimiento de Tickets (OCR): Integré la API de Mindee para que, al subir una foto de una factura, la IA extrajera automáticamente la fecha, el monto total y la categoría.
  • Control por Voz: Implementé la Web Speech API nativa del navegador para poder dictar gastos (ej: "Comida 20 euros") y que la app lo procesara.
  • Visualización de Datos: Integré Chart.js para gráficos interactivos y Leaflet para un mapa de gastos geolocalizados.

Fase 4: Identidad y Datos

Para que VELUT se sintiera como un verdadero centro financiero personal, trabajé en enriquecer las secciones de "Mercado" y "Perfil".

💡 Idea Si el usuario ve datos reales del mercado (Bolsa, Cripto) dentro de la app, aumentará su retención. No solo entrará para registrar un café, sino para ver cómo va el mundo financiero.

Conecté APIs de Finnhub (para acciones como Apple o Tesla) y CoinGecko (para criptomonedas). También implementé un sistema de Perfil Avanzado que genera un código QR único basado en el email del usuario, y permití la exportación de todos los datos en formato JSON para que el usuario tenga el control total de su información.

Fase 5: La Gran Refactorización (Multi-Wallet)

Llegado a este punto, la app era funcional, pero me di cuenta de un error estructural crítico en el diseño de la base de datos: La app solo permitía un saldo global único por usuario. En la vida real, la gente organiza su dinero en "Efectivo", "Cuenta Banco", "Ahorros", etc.

🚧 El Gran Obstáculo Técnico Tuve que pedirle a la IA que me ayudara a reescribir casi toda la lógica de interacción con Firestore. Pasamos de guardar un simple campo numérico balance en el documento del usuario, a crear una nueva sub-colección compleja de accounts para cada usuario.

Esta refactorización fue dolorosa pero necesaria, y habilitó funcionalidades mucho más profesionales como transferencias internas y gestión de cuentas múltiples.

16. Transferencias P2P Firestore Transactions Atomic Operations Implementación de envíos de dinero simulados. Uso de transacciones atómicas para asegurar consistencia de datos (restar emisor / sumar receptor) evitando errores de red.

Fase 6: Experiencia de Usuario Refinada (Splash Screen)

Para dar el toque final de "App Nativa", implementé una pantalla de carga inicial. Esto oculta la carga de datos de Firebase y ofrece una primera impresión mucho más pulida y profesional.

Utilicé un logo SVG animado y una intercepción del flujo de autenticación para mostrar esta pantalla durante unos segundos antes de revelar el dashboard.

📂 Ver Prompt (Resumido): Splash Screen
20. Implementación Splash Screen CSS Animations Auth Flow Control Diseño de overlay HTML con logo SVG animado (`@keyframes pulse`). Lógica JS para interceptar el login exitoso, mostrar el splash durante 2 segundos mientras cargan los datos, y realizar una transición suave (`fade-out`) hacia el dashboard.

Conclusión

Desarrollar VELUT ha sido un viaje de aprendizaje intenso, pasando de una idea básica a un ecosistema financiero complejo. Trabajar con un agente de IA en el IDE Antigravity me permitió abstraerme del código repetitivo y centrar mis esfuerzos en la Lógica de Negocio, la arquitectura de datos y, sobre todo, en la Experiencia de Usuario.

Lo que empezó como un puñado de archivos HTML y JS estáticos se ha convertido en una PWA robusta, instalable, con soporte offline, simulaciones de biometría, una gestión contable profesional multi-cuenta y análisis de datos en tiempo real.
