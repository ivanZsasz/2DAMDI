🚀 Bitácora de Desarrollo: Construyendo el 'Centro de Control Global'

Crear un dashboard para controlar servidores no debería ser una odisea, pero este proyecto me enseñó que la elección de herramientas y, sobre todo, la elección del Asistente de IA, pueden marcar la diferencia entre un éxito rotundo y un fracaso técnico.

Este artículo documenta el desarrollo completo, desde la infraestructura hasta el código final, de mi Centro de Control Global, un sistema basado en Node.js y Multipass.

1. La Infraestructura: El Cambio de Rumbo

Inicialmente intenté usar librerías nativas complejas, pero pivoté hacia Canonical Multipass por su sencillez. Multipass permite levantar instancias de Ubuntu ligeras con un solo comando.

# Despliegue de la infraestructura (2GB RAM cada uno)
multipass launch --name servidor-1 --cpus 1 --disk 5G --memory 2G
multipass launch --name servidor-2 --cpus 1 --disk 5G --memory 2G
multipass launch --name servidor-3 --cpus 1 --disk 5G --memory 2G
multipass launch --name servidor-4 --cpus 1 --disk 5G --memory 2G

2. El Desafío del Desarrollo: Antigravity vs. Gemini

🛑 El Obstáculo: Antigravity (Claude)

Utilicé Antigravity para la interfaz inicial. Fue problemático: Reescribía archivos borrando lógica funcional y creaba código que intentaba conectar por SSH innecesariamente.

✨ La Solución: Gemini (Arquitecto)

Recurrí a Gemini para arreglar el código. Entendió que no se debe tocar lo que funciona, implementó "candados" de seguridad y optimizó el código drásticamente.

3. Obstáculos Técnicos Superados

  • Efecto Zombie: Las máquinas se encendían solas porque el frontend pedía estadísticas a una máquina apagándose. Solución: Bloqueo de 15s.
  • Arranque Lento: Cambié el apagado por Hibernación (suspend), reduciendo el tiempo de encendido de 60s a 4s.

VERIFICACIÓN SEGURA (Promesas)backend/index.js
function getServerStatus(vmName) {
  return new Promise((resolve) => {
    exec(`multipass info ${vmName} --format json`, (err, stdout) => {
      try {
        const info = JSON.parse(stdout);
        const vmInfo = info.info[vmName];

        if (vmInfo && vmInfo.state === 'Running') {
          return resolve('Running');
        }
        resolve('Stopped');
      } catch (e) {
        resolve('Stopped'); // Fallback seguro
      }
    });
  });
}
📝 ANÁLISIS TÉCNICO

Patrón "Graceful Degradation": Si Multipass falla o devuelve datos corruptos (error en JSON.parse), el sistema no se rompe; asume que el servidor está apagado (resolve('Stopped')) y continúa funcionando.

Asincronía: Envolvemos el comando exec en una Promesa para poder usar await en el resto del código, manteniendo la lectura secuencial y limpia.

AUTOMATIZACIÓN (CRON JOB)backend/index.js
setInterval(async () => {
  const now = new Date().toLocaleTimeString('es-ES', { hour: '2-digit', minute: '2-digit' });

  for (const [id, schedule] of Object.entries(schedules)) {
    
    // TAREA DE APAGADO AUTOMÁTICO
    if (schedule.stop === now && status === 'Running' && !shutdownLocks[id]) {
      
      logSystem('⏰', `Ejecutando tarea: APAGANDO ${server.name}...`);
      
      // 1. Activamos candado para bloquear usuarios
      shutdownLocks[id] = true; 
      
      // 2. Ejecutamos hibernación
      await runLocalMultipass(`multipass suspend ${server.multipassName}`);
    }
  }
}, 30000); // Revisar cada 30 segundos
📝 ANÁLISIS TÉCNICO

Automatización: Este bucle infinito actúa como un reloj interno que comprueba cada 30 segundos si hay tareas pendientes.

Seguridad (Locks): La variable shutdownLocks es fundamental. Impide condiciones de carrera ("Race Conditions") evitando que el sistema intente apagar un servidor que un usuario ya está manipulando manualmente.

📌 Conceptos Clave Aplicados

Async / Await

Sintaxis moderna para gestionar operaciones lentas (como encender una VM) sin congelar el resto del programa.

Polling

Técnica donde el cliente pregunta cada segundo al servidor "¿Hay datos nuevos?". Más simple que WebSockets para este caso.

Race Conditions

Solucionadas mediante "Candados" (Locks) que aseguran que dos procesos no modifiquen el mismo recurso a la vez.

Fase 3: Blindaje (Fix Gemini)

Situación: Las máquinas se reiniciaban solas por el bug del frontend.

"Actúa como Arquitecto de Software. Tengo un bug crítico: las máquinas se reinician solas.
1. Bug del Reinicio: Antes de ejecutar `free` o `top`, verifica PRIMERO el estado con `multipass info`. Si no está 'Running', devuelve 'offline' inmediatamente.
2. IPs Dinámicas: Haz que el sistema detecte las IPs al arrancar."
Fase 5: Automatización Final

Situación: Implementar el programador de horarios sin romper el código.

"Necesito implementar un Programador de Horarios sin romper lo que ya funciona.
1. Frontend: Crea una ventana Modal oculta con inputs para 'Hora Inicio' y 'Hora Fin'.
2. Backend: Crea un objeto en memoria `schedules` y un `setInterval` que revise la hora cada 30 segundos.
3. Logs: Crea una función `logSystem` que imprima en la terminal con emojis cada acción."

6. Resultado Final

El resultado es un sistema robusto, capaz de gestionar servidores reales con una latencia mínima y una interfaz moderna.
